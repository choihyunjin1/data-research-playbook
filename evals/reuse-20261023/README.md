# 새 문맥 작업자의 재사용 시험

기대 정답이나 원 채팅 없이 README부터 시작한 작업자가 전력계 코드 오류와 해로운 보정 반례를 찾아 실행했습니다. 이는 **한 번의 경로 찾기·적용·인계 시험**이지 스킬 효과의 A/B 검증이나 생산성 점수는 아닙니다.

## 실제 관찰

- 식별자 절삭, NaN/Inf의 clip 통과, 구간을 넘는 평균을 찾아 고쳤고 별도 11개 검사가 통과했습니다.
- 같은 시간 창이라도 양끝 포함 규칙이 다름을 발견했습니다. 기존 pandas rolling의 `(t−30분, t+30분]`을 보존하고, 저장소의 양끝 포함 함수를 그대로 대체하지 않았습니다.
- 합성 공백의 일평균: 정답 10, 시간 보간 10, 경계잔차 보정 9.75. 추가 정보 사용이 항상 도움이 되지는 않는 반례를 설명했습니다.
- 가린 정답을 바꿔도 방법 입력과 결과는 불변이었습니다. 학습·원자료 다운로드·새 지점 탐색은 하지 않았습니다.
- 별도 간단한 요청 `80의 25%`에는 `20`을 답했습니다. 이 한 건을 스킬 과잉 적용률로 일반화하지 않습니다.

## 평가 요청의 모호함과 수정 범위

요청에는 정확한 공백 시각과 수심이 빠졌습니다. 작업자는 ‘가운데 6시간’을 09~14시로, 수심을 고정 함수 기본값으로 해석하고 이를 인계에 밝혔습니다. 작성자의 비공개 예상은 다른 시간 구간을 상정했으므로 그 예상 숫자로 정오 판정하지 않았습니다. 동일 합성 입력에서 이웃층 차이는 상수라 수심 가중치의 상수항이 잔차에서 소거됩니다. 계산을 별도로 확인했지만, 실제 적용에서는 공백 시각·변수 단위·배치 메타데이터를 먼저 명시해야 합니다.

작업자는 반복 블록명 `a,b,a`를 거부하는 추가 정책도 적용했습니다. 구간 간 오염 방지에는 타당하지만 요청에서 직접 정한 조건은 아니므로 원 시스템 반영 전 확인할 사항으로 남깁니다. 놓친 오류가 없다는 완전성 보증은 아닙니다. 이 시험 후 공통 평균 함수 문서와 경계 회귀 검사 1개를 보완했으며, 작업자의 답을 다시 유도하거나 점수를 올리기 위해 시험을 반복하지 않았습니다.
