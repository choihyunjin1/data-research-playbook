# 사건에서 남긴 작업 방식

기존 사건원장의 발생·원인·조치·검증을 요약했습니다. 과거 문서의 관찰과 이번 공개 저장소의 실행은 구분합니다. [원본 식별자](provenance.json)에 연결했으며, 원 기록에 없는 손실 시간·비용·거짓 제출 사실은 추정하지 않았습니다.

## 버전과 완료 상태

| 사건 | 확인된 문제 | 이후 작업 방식 | 관찰된 검증과 남은 범위 |
|---|---|---|---|
| EV-L01 정본 불일치 | 상위 안내의 P2·P3 SHA와 최종 선택 SHA가 달랐음 | 실제 현재본·입력·receipt를 연결하고 과거 안내는 이력으로 구분 | identity 불일치 합성 검사는 통과. 당시 잘못된 모델을 실제 제출했는지는 확인 안 됨 |
| EV-L02 반복 시도 | 프로브·확인 비중이 높고 브라우저 연결/확인창에서 멈춘 기록 | 마지막 관찰·실패 단계·바뀐 조건·새로 얻을 관찰을 구별 | 합성 재시도 계약과 외부 상태 과제 검사. 같은 실패 재시도의 실제 횟수·시간 절감은 미측정 |
| EV-L04 출력 버전 혼용 | 대본을 먼저 고친 뒤 PPT 노트·연습 HTML이 구판인 과도 상태 | 정본 하나와 영향을 받는 출력의 변경/불변 집합을 대조 | identity와 실제 산출물 검사를 분리. 구판으로 실제 발표했다는 증거 없음 |
| EV-L05 시도와 접수 | 준비 파일·답안 제출·모델 제출·메일/운영진 접수의 상태가 서로 다름 | 준비→시도→서버 반영→수신 확인을 분리하고 중복 쓰기 방지 | 합성 외부 상태 판정. 당시 기록을 현재 서버 상태 확인으로 대신하지 않음 |

작업에 적용할 입구는 [인계 playbook](../../playbooks/handoff.md)입니다.

## 발표에서 확인한 문제

**EV-L03:** 파일·렌더 검사는 통과했지만 AI 활용 장의 소재가 청중 질문에 답하지 못했습니다. 후보 탈락 기록을 새 접근을 구체화하는 장에 배치해 역할이 어긋났습니다. 뒤의 수정은 제목만 바꾼 것이 아니라 소재와 비중을 교체했습니다. 이 사건이 증명하는 것은 기술 검사와 내용 검토가 다르다는 점입니다. 사람의 이해율을 실측한 것은 아닙니다.

**EV-L06:** 대회가 요구한 여섯 미래 출력 자체를 고유 장점으로 내세우거나, 비교군·집계 단위가 다른 개선율을 하나로 옮길 위험이 있었습니다. 보간과 전체 복원 방식의 일평균 비교를 시간 평균 단독 기여로 설명할 수 없습니다. 그 뒤에는 변경점·그대로 둔 것·단위·분모·선택 노출·제안 여부를 수치 옆에서 확인하도록 했습니다.

이를 자동 인증하는 완성형 검사기는 없습니다. 그림·발화·근거를 실제로 대조해야 합니다. [결과 전달 playbook](../../playbooks/communicating-results.md)에 적용 방식을 남겼습니다.

## 코드 계약에서 실제로 확인한 문제

| 실패 모양 | 개발용 수정과 확인 | 공개 재사용 범위 |
|---|---|---|
| 층 `2.9`를 정수 변환해 `2`로 허용 | 변환 전 정수성·허용값·결측 검사; 정상 정수 유지 | `exact_integer`의 합성 예제 |
| 원 예측 `±Inf`가 clip 후 정상 유한값처럼 보임 | 원예측·합산값을 clip 전에 검사; 유한 범위 초과값의 clip 유지 | `finite_clip`의 합성 예제 |
| 시간 평균이 평가 블록 경계를 넘음 | 명시적인 블록·시각 경계 안에서 평균과 지원 수 계산 | 한 시계열의 `boundary_mean`; 프로젝트 전체 평균기 대체 아님 |
| P3 기준 시각 결측을 이전 값으로 대체 | 정확한 기준 시각을 검증하고 조용한 대체 거부 | 당시 개발용 계약; 전체 모델을 이 저장소에 복제하지 않음 |
| P2 서로 다른 관측소 endpoint 혼입 | 단일 관측소 계약, 불완전 프로필 원값 유지 | 당시 개발용 함수 검사 |
| P1 평가 자료가 수심 메타데이터 계산에 참여 | 학습 측에서만 계산하고 적용 분리·캐시 조건 갱신 | 당시 합성 불변성 검사; 실제 재학습 결과 아님 |

당시 최종 합성·통합 검사 수는 130개였습니다. **130개는 생산성 점수나 실제 모델 재현 인증이 아닙니다.** 가짜 모델·합성 입력 경로와 수정 함수의 실패 차단을 확인한 범위입니다. 현재 공개본의 검사는 [현재 검수 기록](../../reports/VALIDATION.md)으로 따로 확인합니다.

검사기에도 빈 실행을 PASS로 보고하거나 하위 실패를 누락할 위험이 있어 실행 수·실패·프로세스/출력 증거를 대조했습니다. 단순한 PASS 문자열, 파일 존재, 직접 적은 SHA만으로 완료를 판정하지 않는 이유입니다. 구체적인 작업 입구는 [코드 계약 playbook](../../playbooks/code-contracts.md)입니다.
