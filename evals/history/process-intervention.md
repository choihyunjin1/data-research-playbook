# 추가 지침과 새 작업자 인계

## 체크리스트를 더 붙여도 차이가 없었던 비교

첫 스킬을 축소한 뒤, 기존 공통 v2·분야 지침 조건과 여기에 별도 개입 문서를 더한 조건을 비교했습니다. ‘아무 지침도 없음’과의 비교가 아닙니다. 코드·기술 글·발표·실행 상태를 다루는 **같은 네 합성 과제**를 두 새 문맥 쌍이 수행했고, 두 번째 쌍에서는 제시 순서를 뒤집었습니다.

두 쌍의 두 조건 모두 요청 산출물 4/4를 충족했고 확인된 필수 내용 실패는 0/4였습니다. 수정된 네 함수에 같은 24조건을 실행했을 때 각각 통과했고, 원 함수에서는 8조건이 실패했습니다. 이는 코드 수정의 효과입니다. 추가 지침을 받은 쪽만 좋아졌다는 결과가 아닙니다.

추가 조건의 한 실행에는 선택적으로 보고한 소스 SHA 오류가 있었습니다. 실제 함수 검사 결과와 보고 지문을 분리했고, 과거 오류를 지우지 않았습니다. 이 한 건만으로 추가 지침이 오류의 원인이라고 단정하지도 않았습니다.

따라서 추가 개입을 필수 표준으로 채택하지 않았고, 수기 SHA 중복 기록을 줄였습니다. 같은 노출 과제를 반복해 더 좋은 AI 점수를 얻는 단계는 종료했습니다.

## 인계가 실제로 작동한 범위

새 문맥 작업자에게 최소 운영 입구와 요청만 제공했습니다. 가짜 모델의 정상 실행은 26행·986 bytes CSV와 receipt를 만들었고, 잘못된 층 식별자 `2.9`는 거부했습니다. root는 현재 CSV 행 수·크기·해시와 실패 출력의 부재를 별도로 대조했습니다.

이 검사는 **로컬 입구에서 필요한 경로를 찾아 합성 작업을 수행할 수 있었다**는 증거입니다. 공개 저장소의 새 clone, 다른 OS·장비, 자동 스킬 선택, 실제 모델 성능, 장기 생산성은 당시 검사가 아닙니다.

## 해석에 남긴 제한

- 같은 네 과제의 반복이므로 16개 독립 과제로 세지 않습니다.
- 배정·포장 규칙 일부는 사전 SHA 봉인 대상이 아니었습니다. 현재 매핑의 정합과 과거 불변성 인증은 다릅니다.
- 일부 과거 행동과 전체 도구 이력은 독립 확인하지 못했습니다. 내용 실패 0건과 구분합니다.
- 사용자 재작업 시간·비용·토큰·실제 청중 이해·자연 작업 성과는 미측정입니다.
- 합성 검사의 통과를 보안 Deep Scan 완료로 바꾸지 않았습니다. 당시 Deep Scan 연결 실패는 미완료로 남았습니다.
