# 잘못된 입력이 정상 출력으로 바뀌는 지점 검사

## 먼저 볼 반례

원 작업에서는 소수 층 식별자 `2.9`가 정수 변환으로 `2`처럼 처리될 수 있었고, 무한대 예측은 clip 뒤 정상 범위처럼 보일 수 있었습니다. 최종 파일의 열과 범위만 검사하면 놓치는 결함입니다. [계약 검사 이력](../evals/history/incidents.md#코드-계약에서-실제로-확인한-문제)은 정상 회귀와 구분해 기록합니다.

| 변환 경계 | 반례 | 정상 동작도 함께 보존할 조건 |
|---|---|---|
| 식별자→정수 | `2.9`, NaN, 정밀도를 잃는 큰 수 | 허용 범위의 정수·정수 문자열 |
| 원예측→clip | NaN, ±Inf, 합산 overflow | 유한한 범위 초과값의 의도한 clip |
| 시각→기준 관측 | 기준 시각만 결측 | 정확한 기준 시각, 순서가 다른 유효 입력 |
| 학습 전처리→평가 적용 | 평가 메타데이터를 바꿨더니 학습 변환도 바뀜 | train-only 통계와 명시적 unknown |
| 시간 평균→평가 블록 | 행이 인접하지만 평가 블록은 다름 | 같은 블록 내 실제 시간 거리·지원 수 |
| 출력→PASS receipt | 빈 검사·실패 subTest·잘못된 peer 파일 | 실제 실행 종료와 실제 파일 대조 |

관련 함수에서 **수정 전 실패 / 수정 후 차단 / 정상 입력 유지**를 확인합니다. 원래 동작이 맞던 부분까지 일괄 재작성하지 않습니다. 계약 함수가 보장하는 입력 범위와 정책값은 도메인 코드에서 분리합니다.

외부 수집의 추가 반례는 [공유 URL 연결 격리와 최신 미확인 가격](../cases/savetax-crawler/README.md#공개한-재현과-비공개-원본)에 있다. 그 합성 검사는 운영 크롤러의 과거 응답이나 가격 정확도를 검증한 결과와 구분한다.

## 파일 동일성과 실행 검증

역사적 정확 재현은 정해진 입력·버전에서 같은 SHA를 요구합니다. 현재 실행 검증은 입력·코드·설정, 별도 프로세스, 실제 출력과 비교 오차를 기록합니다. 후자가 통과했다고 과거 답안과 바이트가 같아진 것은 아닙니다.

receipt에 PID나 SHA 문자열이 있다는 사실도 실행 증거를 대신하지 않습니다. 해당 프로세스의 종료와 출력 파일을 직접 연결하고, 출력 충돌 시 다른 작업의 파일을 지우지 않도록 검사합니다. 로컬 receipt는 서명된 외부 인증서가 아닙니다.

## 여기서 멈출 기준

변경한 계약과 관련 정상 입력이 통과하면 그 범위를 보고합니다. 합성 테스트를 실제 모델 재생·보안 감사·성능 향상으로 확대하지 않습니다. 변경되지 않은 전체 연구를 진척 표시용으로 다시 실행하지 않습니다.
